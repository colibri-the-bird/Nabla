# Nabla: организация локального проекта

> Этот файл — организационная памятка. Он не является нормативной спецификацией Nabla и не изменяет приоритет документов проекта.

## Кратко о проекте

Nabla — локально-первичная персональная система для знаний, обучения и личных данных. Спецификация описывает:

- Markdown-заметки, документы и PDF с аннотациями;
- модульное ядро, capability-контракты и проверяемые команды;
- журналирование, отмену и компенсацию смысловых изменений;
- локальное владение данными, синхронизацию и резервное копирование;
- ограниченное и подтверждаемое взаимодействие с ИИ.

План развития разбит на три этапа:

1. Desktop-ядро, заметки, документы и PDF.
2. Обучение, аналитика, мобильное приложение и синхронизация.
3. Интеграция облачных и локальных моделей ИИ, OAuth и API.

На текущем этапе это прежде всего подробный комплект спецификаций. Реализационного кода приложения пока нет; единственный инструмент — `tools/spec_slice.py` для выборочного извлечения разделов спецификации.

## ChatGPT и Codex

В ChatGPT уже существует проект `Nabla`, содержащий пять тематических чатов. Это подходящее место для живой истории обсуждений. GitHub не синхронизирует сообщения ChatGPT или Codex автоматически: в Git можно хранить только явно экспортированные Markdown-файлы и индекс.

Для новых локальных задач Codex следует выбирать эту папку как проект. Тогда все задачи будут работать с одним Git-репозиторием и одной версией файлов. Старые чаты останутся в проекте ChatGPT `Nabla`; их перечень сохранён в `chats/INDEX.md`.

## Публикация на GitHub

Рекомендуемый вариант — приватный репозиторий, пока не выполнена проверка на персональные данные, секреты и нежелательные для публикации проектные материалы.

После создания пустого приватного репозитория `nabla` на GitHub:

```powershell
git remote add origin https://github.com/<ВАШ-ЛОГИН>/nabla.git
git push -u origin main
```

Не добавляйте на GitHub пароли, API-ключи, токены, приватные данные или неочищенные экспорты чатов.
